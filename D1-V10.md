# Shared database v1 — 2026-10-26

Sites provisions D1 binding DB. Five migration-owned tables contain public game data and upstream request control only. No browser libraries, player identifiers, ratings or recommendation output are persisted. The two API routes require D1; database failure does not bypass quota protection.

## Active tables
- games: canonical Steam App ID, source-derived name; nullable product type and parent ID remain unknown until validated.
- game_sources: unique provider/external ID mapping, source-specific versioned JSON, retrieval and expiry timestamps. steam-tags v2 is populated by successful exact-App-ID feature enrichment. IGDB mapping is reserved, not connected.
- api_cache: shared JSON response cache and per-key refresh lease, failure status/backoff. Dictionary 24 h, search 5 min, details/review summaries 10 min. Features 7 days. Cache keys include endpoint, language and region. No final personalized recommendation is cached. Cache cleanup deletes at most 50 expired inactive rows older than 24 h per successful miss; this is opportunistic, not a scheduler or hard storage cap.
- api_quota: shared atomic fixed-minute counters: 80 total, 2 dictionary, 36 search, 30 details, 15 reviews. Existing per-isolate spacing/admission still applies. Fixed windows permit boundary bursts; this is not a distributed smooth queue. 429 cooldown is shared. Upstream policy may additionally return an isolate cache hit, which conservatively consumes a shared count.
- game_observations: reserved, initially empty, extensible public observations with source/method/version/scope/time/sample count. No automatic AI enrichment.

Concurrent identical cold requests acquire a D1 lease: one fetches, others receive a retryable rate-limit signal rather than duplicating upstream work. Lease expires after 10 min to cover the bounded existing upstream queue; process termination can delay retry until expiry. No waiting job queue, automatic background refresh or scheduled cleanup is enabled.

## Future observation contracts
Each payload must be validated when its provider is implemented. Unknown values are null/absent, never invented zeroes. A future schema migration is appropriate when fields need indexed queries.

| category | scope | payload / interpretation |
|---|---|---|
| gameplay / presentation | taxonomy version | feature values; method source_fact, rule_inference, or ai_inference and model/rule version |
| playtime | platform + sample population | unit=minutes, completion type, median/percentiles, sample count; no cross-genre raw-hour ranking |
| reviews / popularity | language + time window | counts, score, measurement type; proxies must not be labelled actual player counts |
| price | store + country + currency | integer minor units, original/final price, discount end; time series required before claiming historical low |
| compatibility | platform + language | OS/controller/language/multiplayer conditions |
| relationship | relationship type | parent, DLC, demo, remaster, franchise; validated external identifiers |
| release_update | edition + platform | release/early-access/major update date and source |

Player library snapshots, wishlists, preferences, recommendation runs/impressions/feedback are reserved as separate future modules, not anonymous public tables. Before activation: authenticated subject, owner-scoped reads/writes, consent/retention/deletion, algorithm version and feature snapshot references. Clicks/wishlists are intent, not proof of enjoyment. No endpoint accepts writes to public metadata from arbitrary client feature payloads.

## Migration and recovery
0000 is an additive, schema-only first migration. No pre-existing hosted D1 existed before this change; no prior user DB to export. Generated SQL and Drizzle metadata are committed. Applied migrations must remain immutable. Older v9 code does not use D1, so code rollback can leave these tables intact. Do not drop the DB on rollback.

Schema and source backup are not data backup. Automated D1 export/restore, retention and disaster recovery remain to be configured and tested before storing irreplaceable player data. Current public cache is reconstructible. Verify expiry, cross-instance reuse, shared quota, malformed upstream, exact game upsert, and fail-closed DB behavior using shared-store-tests.mjs; these run real SQLite with a D1-shaped adapter, not hosted D1. Hosted migration/table verification is separate.

## Deployment verification
